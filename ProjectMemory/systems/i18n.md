# i18n (app language EN / TR)

**Files:** `js/i18n.js` (engine), `js/data/i18n-en.js` (core UI), `i18n-en-ads.js` / `-ads2.js` / `-ads3.js` (Carmen.com, Gothic, Meisove ad texts), `i18n-en-labels.js` (traits, zodiac, themes, effects), `i18n-en-ui2.js` (news, Lia, Monia), `i18n-en-sites.js` (sites, game UI), `i18n-en-books.js` (books), `i18n-en-misc.js` (Fiery days/places/items, place names), `i18n-en-events.js` (event descriptions, Bot lab, guide), `i18n-en-bot.js` (event bubbles), `i18n-en-chat.js` (chat bubbles). `i18n-en-tools.js` loads only in `tools/bot-editor.html`, never in index.html (keeps rule-word chips Turkish). Loaded right after `store.js` in `index.html`; listed in `sw.js` CORE. Language picker: app.js `renderMe` → Ayarlar (`#langPick`, reloads page).

## How it works
- Source code stays Turkish. `Stories.I18n` translates what reaches the DOM: a MutationObserver walks added nodes (text + `placeholder/title/aria-label`); `alert/confirm/prompt` are wrapped.
- Language: `localStorage amor-stories:lang`, default `en`. Effective language of a node = nearest `[data-lang]` or app language; only `en` nodes are translated.
- Dictionary key = Turkish text without leading/trailing emoji/punctuation (trailing `.!?…)` kept). `{}` / `{ad}` placeholders become regex patterns (filled in order, `{0}` `{1}` for reorder); most specific pattern wins (sorted by literal length). Fallbacks: sentence split, then ` · ` split.
- SKIP (never translated): chat message text without `data-lang` (`.msg .bubble`, see Chat bubbles), `.evb-t`, `.ocb-t`, `.sys`, scene text, captions, quotes), `textarea`, `code`, `.no-i18n`. Bot messages stay Turkish (by request, for now).
- Ad sites: `adLang(c)` (app.js, near `cmBadge`) = `tr` if app language is `tr` (all sites fully Turkish) or `World.regionOf(c.city) === 'Türk'`, else `en`. `countryOf` prefers a foreign country because Türkiye's city list also holds foreign cities. Set as `data-lang` on ad cards and on ad profile / meet pages (whole page follows the girl's language). `cmAbout/gtAbout/msAbout` build the interpolated sentences in English directly (`adIntroEn`, `adT`).

- Two stores: `main` (screen) and `side` (read only by `I18n.line(s)`, bubble rules). `I18n.toSide(true)` before a dictionary script sends its keys to `side`. `tools/bot-editor.html` loads `i18n-en-bot.js` + `i18n-en-chat.js` this way, so rule words and chips are never translated.

- `I18n.add` with a pattern key already in the store updates its text (`K` map), so a later `add` wins for patterns as it does for plain keys. `I18n.keyOf(s)` returns `[lead, key, tail]`. The bot editor's English tab uses both (see bot.md).

## Chat bubbles
- Stored message text stays Turkish; only the DOM changes. `itemHtml` (app.js) sets `data-lang` on normal bubbles only when the app language is `en`: `adLang(speaker)` for `her`, `m.ml` for my event messages. App language `tr`: no `data-lang`, all bubbles Turkish. Bubbles without `data-lang` stay in SKIP (messages you type, old me-lines).
- In app language `en`, `tr` characters stay Turkish and `en` characters translate. A character with no city counts as `en` (same as `adLang`).
- Dictionary `i18n-en-bot.js`; `||` parts are separate keys, `{sen}` `{o}` are patterns, reply lines with `{x:y}` tokens are skipped. Tone adds (personality suffix, moans, stretched letters) can break exact match: unmatched text stays Turkish.
- Logic and bot rules must keep reading stored Turkish, never DOM.
- `i18n-en-chat.js`: traitless rules of Selamlaşma, Romantik, Sohbet, Sorular, İltifat, Sevişirken + all of Yaşa göre (trait rules score +10 per trait, so age variants win for every aged character; check the winning rule, not only the traitless one). Lines mentioning school, campus, family or "abla" stay Turkish; "küçük" addressing the user becomes "young man". `{v}` key placeholder = bubble-only pattern (`p.b`, skipped outside bubbles so "Bana {v} yap" can't touch UI text). Fills split on ` ve ` → ` and `. Patterns are case-sensitive, so lowercase-style bubbles match only exact keys.
- `{hatıra}` lines are not translated: the fill is a Turkish memory sentence, the bubble would be half Turkish.
- Not supported yet: Turkish `{sen}`-style words outside canım/tatlım/aşkım/bebeğim, `{gogus}`/`{kalca}`/`{sik}` fills.

## Coverage
Phase 1: nav, home, match, messages, profile, chat UI, create, Me/onboarding, Carmen.com/Gothic/Meisove.
Phase 2: news, Lia, Monia, Booble, Choise, Fans, Stay, Shop, Klinik, Jobs, Confessly, Creative, Gram, Flix, Live, Party, Problematic Subjects, Fiery UI + map/days/items, place names, books.
Also: bot editor UI, event descriptions, Bot lab (rule words and answers in the editor stay Turkish; they are bot data).
NOT yet: Fiery story (`fiery.js` characters, scenes), `places.js` scene texts, trait-specific chat rules, remaining bot categories (see status.md).
Skipped on purpose (stay Turkish): CarmenSchool, Campus / student-teacher titles and lines (Flix, Jobs, books, role pairs), student costume offers, and Fiery sexual scenes with student-coded characters or school settings. Text that only reaches chat bubbles is skipped too (SKIP never translates it). Commands the user types in books stay Turkish: the bot only reads Turkish.

## Change safety
- New UI string → add `'Türkçe': 'English'` to the right dictionary, otherwise it shows Turkish in EN mode.
- Never add keys that can be people's names (Gül, Lila, Başak, Yağmur, Ela were removed): exact text nodes like character names would be "translated".
- Logic must never read translated DOM text; data values (traits, event titles, session names) stay Turkish in state.
- Coverage check scripts used during build: extract Turkish quoted strings in a line range and test `I18n.translate` under Node with DOM stubs.
